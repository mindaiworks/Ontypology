# 寫在前面：三個約定

這是一本談「AI 怎麼把機械設計與 PLM 文件產出做準」的書。它不重講理論、不展示系統程式，而是把一套認知工具直接用在機械研發現場：讓規格、零件、組裝、檢驗、變更、履歷這六種產出，每一條數字都說得出自己從哪裡來。

為了讓後面所有章節都走在同一條軌道上，先立三個約定。

> **約定一・形的英文是 Type**
>
> 本書所說的「形」，英文一律用 Type，不用 Form。
> 因此有 SpecType（規格形）、PartType（零件形）、AssemblyType（組裝形）等；Type-Driven Design 即「形驅動設計」。

> **約定二・理論只用不教**
>
> 本形學（空間本形與時間本形）是本書的理論基礎，但本書不重述它的內文。
> 書中只使用它的工具：三括號 [ ] { } ( )、交集判準 ∩(T)、身份錨 id(C)、remove 三級、框架四步驟、三層判斷、招式盤。
> 想知道每個工具背後的推導，請回讀理論原著；本書負責把工具用對地方。

> **約定三・平台只引不述**
>
> 底層平台是 Mind AI：它提供統一知識模型、推理引擎、記憶與自我演化能力。
> 本書不重述平台內容，只在需要處引用它的分工位置——工程師的對話對象是 Mind AI，判準與證據留在形庫裡。

三個約定一句話總結：形 = Type，理論當工具用，平台當底座用。

# 第一章　認識 AI 機械設計與 PLM 大腦

![image3.png](PIC/image3.png)

先把主角請出來：一台 AI 機械設計與 PLM 大腦。它不是一個會聊天的 CAD 助理，也不是一台文件產生器——它是一個能把「產品是什麼」記住、「設計為什麼」推理出來、「改了之後影響誰」算清楚的大腦。本章用四節交代它的定位：產品副本、雙本形落點、平台分工，以及「產出準確」這四個字到底從哪裡來。

## 1.1　可推理的產品副本：形＋數

每個機械案子在電腦裡都有一個「副本」：BOM、圖檔、規格書、變更記錄。但傳統的副本是一堆檔案——人看得懂，AI 讀不懂關係。可推理的產品副本要求副本裡的每一個東西都是一個形（Type）：零件是形、組裝是形、規格是形、變更是形。形有名字、有邊界、有組成、有判準，AI 才能對它提問並得到有意義的答案。

![image4.png](PIC/image4.png)

**圖 1-1　產品副本 = 形 + 數：先辨識結構，再計算參數**

以本書的貫穿案例——一級行星減速機——來說。「行星減速機」這個形回答是什麼：由太陽輪、行星輪、齒圈、行星架與殼體組成，缺了太陽輪就傳不了動。而 i = 5、η = 95%、額定輸出扭矩 50 N·m 這些數，回答它有多強。數不能脫離形而單獨存在：沒有「行星輪系」這個形，「齒數 27」這個數毫無意義。先有形，才有數——這是產出準確的第一個習慣。

**表 1-1　「產出不準」的四種現場與形的處方**

| 現場症狀 | 真正原因 | 形的處方 |
| --- | --- | --- |
| 同一零件在不同文件裡對不上 | 沒有立形、名字漂移 | 立零件形，用 id(C) 錨住身份 |
| 規格寫了卻無法驗收 | 沒有量化判準 | 規格形內建 ∩(T) 驗收條款 |
| 變更之後文件漏改 | 沒有依存鏈 | 組裝形 BOM + remove 三級影響分析 |
| AI 產出看起來合理卻不敢用 | 數字沒有出身 | 形證據鏈：每個數字標註來源 |

這個分工對「準確」有直接意義：LLM 生成的文字天然帶有統計上的模糊，而形庫裡的判準是確定的。讓語言歸語言、判準歸判準，AI 的產出才敢蓋章。

## 1.4　「產出準確」從哪裡來

「產出準確」不是一個口號，而是四道保險的合成。第一道是判準：每個形帶 ∩(T) 交集判準，進得來的產出才算了數。第二道是推導：結論不是抄來的，是沿演繹骨架一步步推來的。第三道是驗證：算完的數字要過工程驗證——公差鏈、強度、性能。第四道是追溯：形證據鏈讓每個數字都能回溯到源頭。

**表 1-4　四層準確性（預告）**

| 層 | 守什麼 | 一句話 |
| --- | --- | --- |
| 第一層 | ∩(T) 交集判準 | 交集不滿，不得入形 |
| 第二層 | 演繹骨架 | 結論不是抄來的，是推來的 |
| 第三層 | 工程驗證 | 數字算完還不夠，驗證過關才算數 |
| 第四層 | 形證據鏈 | 任何產出都可回溯到形與判準 |

*表 1-4　第三章逐一拆解這四層；本章先掛出地標。*

> **本章重點**
>
> 可推理的產品副本 = 每個東西都是形；先形後數。
> 雙本形：空間三軸立結構，時間招式定方法。
> LLM 負責語言、Mind Model 負責智慧——準確來自判準，不來自流暢。
> 產出準確 = 判準 + 推導 + 驗證 + 追溯，四層缺一不可。

## 2.1　設計規格形 SpecType

規格形是產出鏈的源頭：客戶一句「我要一台小體積、大扭矩的減速機」，經過規格形變成可驗收的條款。它的要點是每條需求都量化為判準——沒有判準的條款不是規格，是願望。

**表 2-2　設計規格形 SpecType 關鍵欄位**

| 欄位 | 說明 | 行星減速機範例 |
| --- | --- | --- |
| 規格編號 | 唯一身份 | SPEC-PG-001 |
| 需求條款 | 原始需求原文 | 客戶要求減速比 5:1 |
| 量化判準 ∩(T) | 可驗收的數值範圍 | i = 5 ± 2%；T2 ≥ 50 N·m |
| 約束條件 | 邊界與限制 | 外徑 ≤ 120 mm；重量 ≤ 3.5 kg |
| 驗收方式 | 怎麼判定合致 | 空載跑合 + 額定扭矩測試 |
| 溯源 | 來自哪次會議／哪份報價 | RFQ-2026-0815 第 3 條 |

*表 2-2　量化判準欄就是 ∩(T) 的落點：規格形自己帶驗收標準。*

## 2.2　零件形 PartType

零件形是 BOM 的葉子：每一個不可再拆（就本案而言）的零件立一個形。它記的不只是尺寸，還有材料、熱處理、公差與圖號——缺一欄，下游的採購、加工、檢驗就各自猜測。

# 第三章　四層準確性保證

![image12.png](PIC/image12.png)

上一章把六種產出形立了起來；這一章回答「憑什麼說它準」。答案是四層保險：∩(T) 交集判準守住「算不算」，演繹骨架守住「推沒推」，工程驗證守住「驗沒驗」，形證據鏈守住「查不查得到」。四層從入口排到出口，任何一層失守，產出就降級為「僅供參考」。

**表 3-1　四層準確性總表**

| 層 | 保險對象 | 工具 | 失守的症狀 |
| --- | --- | --- | --- |
| 第一層 | 資格：算不算這個形 | ∩(T) 交集判準 | 什麼都收，形庫變垃圾場 |
| 第二層 | 推理：結論怎麼來的 | 演繹骨架 | 數字正確但來路不明 |
| 第三層 | 現實：數字扛不扛得住 | 工程驗證 | 紙面合格、現場失效 |
| 第四層 | 記憶：事後查不查得到 | 形證據鏈 | 同錯再犯、無人負責 |

*表 3-1　四層是疊加關係：全過才是準確，缺一即殘缺。*

## 3.1　第一層：∩(T) 交集判準

每個形都帶一份交集判準 ∩(T)：一組必要條件的交集，全部滿足才准入形。用在機械設計上，∩(T) 就是「四關漏斗」——需求合致、型錄可選、標準合規、判準驗收，關關篩選，關關留據。

![image13.png](PIC/image13.png)

**圖 3-1　∩(T) 四關漏斗：關關篩選，關關留據**

**表 3-2　∩(T) 四關判準範例（行星減速機）**

| 關卡 | 判準內容 | 不滿足時的動作 |
| --- | --- | --- |
| 需求合致 | i = 5 ± 2%；T2 ≥ 50 N·m；n1 ≤ 3000 rpm | 退回 S1 重寫規格形 |
| 型錄可選 | 模數、齒數嚙合條件成立；(Zs+Zr)/行星輪數為整數 | 退回 S2 重選齒形參數 |
| 標準合規 | ISO 1328 六級；ISO 6336 校核 SH ≥ 1.1 | 退回 S3 加大模數或改材料 |
| 判準驗收 | 背隙 ≤ 7 arcmin；η ≥ 94%；噪音 ≤ 65 dB | 退回 S5 開不合格處置 |

*表 3-2　四關的順序不可調換：先問需求，再問選型，後問標準，最後驗收。*

∩(T) 的價值在「擋得住」。沒有判準的產出鏈，AI 生成得再流暢也只是漂亮的猜測；有了判準，猜測在第一關就被擋下——這正是「產出準確」的第一道門。

## 3.2　第二層：演繹骨架

第二層管推理過程：每一個結論都要沿著骨架推導出來，每一步都是「已知 → 公式 → 代入 → 結果」。演繹骨架的反面是「抄答案」：答案碰巧對了，過程卻無人能查——下次換個工況就全錯。

![image14.png](PIC/image14.png)

**圖 3-2　演繹骨架：從需求到參數的推導鏈**

行星減速機的輸入扭矩就是一個典型推導：已知輸出扭矩 T2 = 50 N·m、減速比 i = 5、嚙合效率 η = 0.95；由動力守恆得 T1 = T2 / (i × η)；代入得 T1 = 50 / (5 × 0.95) = 10.5 N·m。這個結果隨後寫入零件形「輸入軸額定扭矩」欄，並在形證據鏈掛上公式來源。齒輪的嚙合條件同理：一級行星傳動比 i = 1 + Zr/Zs，故 Zr/Zs = 4，取 Zs = 18、Zr = 72；再由同心條件 Zr = Zs + 2Zp 得 Zp = 27；裝配條件 (Zs + Zr) / 3 = 30 為整數，三行星輪均布成立。

**表 3-3　演繹骨架推導表（節錄）**

| 步驟 | 已知 | 關係 | 結果 |
| --- | --- | --- | --- |
| ① | T2 = 50 N·m；i = 5；η = 0.95 | T1 = T2 / (i x η) | T1 = 10.5 N·m |
| ② | i = 1 + Zr / Zs | Zr = 4 Zs | Zs = 18，Zr = 72 |
| ③ | 同心條件 Zr = Zs + 2 Zp | Zp = (Zr - Zs) / 2 | Zp = 27 |
| ④ | 裝配條件 (Zs + Zr) / n 為整數 | n = 3 均布 | 90 / 3 = 30 成立 |
| ⑤ | P = T2 x n2 / 9550 | n2 = n1 / i = 300 rpm | P = 1.57 kW |

*表 3-3　每個結果都帶單位，每個公式都有出處——這就是骨架的意義。*

## 3.3　第三層：工程驗證

推導正確還不夠：數字要扛得住現實。第三層是工程驗證——公差鏈疊加、強度校核、性能測試，用物理世界的量測把紙面數字釘死。對 AI 產出而言，這一層是「敢不敢蓋章」的分水嶺。

# 第四章　六步驟：從需求到履歷

![image17.png](PIC/image17.png)

前兩章給了產出的形與準確的保險；這一章給作業法——怎麼把一個案子從需求走到履歷。方法分三層：框架四步驟負責把需求變成維度，六步驟負責把案子走完一圈，三層判斷與招式組合負責在卡住時找到路。

## 4.1　框架四步驟：把需求變成維度

拿到一堆需求先別急著畫圖。框架四步驟——壹・分辨異同、貳・觸發抽象、參・命名維度、肆・判斷歸屬——把雜亂需求整理成一條條維度，讓每個需求都有地方掛。

![image18.png](PIC/image18.png)

**圖 4-1　框架四步驟：從雜亂需求到有序維度**

**表 4-1　框架四步驟 × 需求分析**

| 步驟 | 觸發時機 | 行星減速機例子 |
| --- | --- | --- |
| 壹・分辨異同 | 拿到一群需求 | 「高速款不是重載款」——先分得開 |
| 貳・觸發抽象 | 第二批差異對不上 | 「安裝法蘭不同」對不上「速比不同」 |

## 4.4　挑招・組招・換招

時間本形的招式盤要「用活」：按情境挑單一招是挑招，多招串成套路是組招，卡住換一條路是換招。重載設計案可以「設計搜尋與萃取」挑招起步，接「分析 → 設計 → 推理」組招推進，若正向設計推不動，就換「逆向思考法」或「第一性原理思考法」重新拆解。

![image21.png](PIC/image21.png)

**圖 4-4　挑招・組招・換招：把招式盤用活**

**表 4-3　招式操作示例**

| 操作 | 情境 | 組合 |
| --- | --- | --- |
| 挑招 | 客戶要「同體積更大扭矩」 | 設計搜尋與萃取（找既有極限） |
| 組招 | 全新傳動架構開發 | 分析 → 設計（創造創新）→ 推理（強度因果）→ 重構 |
| 換招 | 參數優化卡在局部解 | 正向思考 → 換水準思考法／第一性原理重新立維度 |

*表 4-3　招式是方法不是腳本：輸入是情境，產出是文件，重用是本分。*

> **本章重點**
>
> 框架四步驟把需求變維度：分辨異同 → 觸發抽象 → 命名維度 → 判斷歸屬。
> 六步驟走一圈：認明情境 → 分軸建形 → 挑選擴式 → 生成產出 → 判準驗收 → 歸檔演化。
> 三層判斷順序固定：容器 → 組成 → 抽象。
> 招式要活用：挑招、組招、換招。

### S1・需求釐清

> **S1 提示詞（需求釐清 → 規格形）**
>
> 你是機械設計工程師。請將下列客戶需求整理為【規格形】設計規格書。
> 要求：(1) 逐條列出需求條款原文；(2) 將每條量化為可驗收判準 ∩(T)（數值＋範圍）；
> (3) 標註約束條件（尺寸、重量、環境、法規）；(4) 寫明驗收方式。

> 輸出欄位：規格編號｜需求條款｜量化判準｜約束條件｜驗收方式｜溯源。

### S2・分軸建形

> **S2 提示詞（分軸建形 → 零件形・組裝形）**
>
> 依據規格形 SPEC-xxx，以三軸建立產品形。
> X 軸 [ ]：列出關鍵屬性與屬性值（名稱｜值｜單位｜來源條款）。
> Y 軸 { }：展開 BOM 至零件層（層級 L0–L2｜編號｜名稱｜數量）。
> Z 軸 ( )：標註容器邊界（殼體／模組／安裝空間，各容器的 id(C) 與邊界描述）。
> 並以 remove 三級為每個部件標註級別：必要件／功能件／身外件。

### S3・推導計算

> **S3 提示詞（推導計算 → 參數推導表）**
>
> 沿演繹骨架逐步推導主參數。每一步輸出四欄：已知｜公式｜代入｜結果（帶單位）。
> 引用標準者標註標準號與條款（如 ISO 6336-1 接觸強度）。
> 禁止只給結論不給推導；若同一參數有多條路徑，擇一為主線、其餘列入備選。
> 最後輸出參數推導表，並標明每個結果將寫入哪一個零件形欄位。

### S4・產出生成

> **S4 提示詞（產出生成 → 零件定義表・BOM）**
>
> 根據形與推導結果生成零件定義表與 BOM 表。
> 零件欄位：零件編號｜名稱｜材料｜熱處理｜關鍵尺寸與公差｜表面處理｜圖號。
> 每一個數值後以【源自：…】標註來源（規格條款編號或推導步驟號）。
> BOM 欄位：層級｜編號｜名稱｜數量｜配合關係｜remove 級別。
> 數值無源者不得出帳；來源不明一律標【待補證據】。

### S5・驗證量測

> **S5 提示詞（驗證量測 → 檢驗形）**
>
> 編寫檢驗規範與報告。逐項輸出：檢驗項｜量測方法｜量具｜判準（引用規格形條款號）｜
> 實測值（可先以模擬值標註【模擬】）｜判定（合格／不合格／讓步）。
> 不合格項必須給出處置建議，並自動開立變更需求草案（交 S6）。
> 禁止現場自創判準；禁止「應該可以」等模糊判定。

### S6・變更管理

> **S6 提示詞（變更管理 → 變更形 ECN）**
>
> 以變更形撰寫工程變更單 ECN。
> 內容：變更編號｜起因｜變更前後對照｜影響範圍｜必做重驗項目｜生效版次。
> 影響範圍必須依 remove 三級與組裝形依存鏈計算，逐形列出（零件形／組裝形／檢驗形／規格形）。
> 一級必要件的變更自動列入必重驗；三級身外件走輕量變更。

### S7・歸檔演化

> **S7 提示詞（歸檔演化 → 履歷形）**
>
> 將本案歸檔為履歷形：版次｜日期｜發行依據｜綁定 ECN 清單｜簽核狀態｜封存處置。
> 並回饋形庫三件事：(1) 可複用的零件形與組裝形清單；(2) 可固化的招式與提示詞修訂；
> (3) 本案誤用與改進（對照第六章誤用五種）。
> 最後輸出下一案的建議起點（從形庫哪個形開始）。

# 回顧收束三問

![image29.png](PIC/image29.png)

**圖 R-1　一張圖收束：理論當工具、平台當底座、六形接成鏈、四層守準確**

讀完六章，收束成三個問題，留給每位讀者帶回自己的現場。

### 第一問・形立起來了嗎？

你的案子裡，每個零件、每個組件、每份規格都是一個形嗎？還是只是一堆檔案？先立形，才有數——這是本書第一個習慣，也是所有準確的前提。

### 第二問・準確守住了嗎？

∩(T) 判準、演繹骨架、工程驗證、形證據鏈——四層保險在你的流程裡各有幾層？缺哪一層就補哪一層，不必一次到位，但必須知道缺口在哪。

### 第三問・明天會更準嗎？

這一次的誤用、這一次的 ECN、這一次的量測意外，都回饋形庫了嗎？L4 自我演化不是平台的魔法，是每個案子結案時那一步「歸檔演化」的累積。

**表 R-1　全書總檢查清單**

| 面向 | 檢查點 | 通過標準 |
| --- | --- | --- |
| 產出形 | 規零組檢變履六形齊備 | 每形有欄位、有判準、有上下游 |
| 判準 | ∩(T) 四關掛進流程 | 不合格產出自動攔下 |
